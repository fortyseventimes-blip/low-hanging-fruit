# Project Context

## Название (рабочее)
low-hanging-fruit — геймифицированный RPG-сервис оценки карьерных навыков
с когортным бенчмаркингом.

## Что это
B2C-сервис, который сканирует профиль человека (резюме, LinkedIn, свободный
текст о себе), показывает его текущую позицию на рынке труда относительно
когорты (индустрия + роль + гео + опыт), визуализирует навыки в виде RPG-карты
(секторы + кольца зрелости + связи между навыками), и строит roadmap
развития с учётом того, какие навыки рынок ещё ценит, а какие уже
автоматизируются ИИ.

## Целевой сегмент (пилот)
Сеньоры на карьерном плато (30–35 лет) и люди в затяжном поиске работы,
преимущественно в IT/продукте — сегмент уже привык к геймификации
(гейминг) и к шерингу данных о себе.

## Ключевые продуктовые решения (зафиксировано)
- Не статичная база — агентный слой поверх БД, ходит во внешние источники
  (MCP) в момент запроса, с кэшированием и окнами свежести.
- Монетизация: партнёрские комиссии с курсов (20–30% ориентир) + быстрый
  трек на платную консультацию.
- Формальные требования рынка (диплом, сертификация) и социальный капитал
  (нетворк, публичные выступления) — это НЕ фильтрующий признак, а
  статистический фактор вероятности, показывается с исключениями
  ("вот люди, которые попали в роль без этого").
- Холодный старт данных — Stack Overflow Developer Survey 2025
  (~49 000 разработчиков, лицензия ODbL, атрибуция обязательна) вместо
  ожидания собственной пользовательской базы.
- Визуальная и структурная логика карты навыков — гибрид: секторы + кольца
  зрелости + связи от PAF Skill Map (Сергей Тихомиров, productframework.ru,
  CC BY-SA 4.0, атрибуция обязательна) как источник логики данных;
  визуальная эстетика — Microsoft Flight Simulator 2024 career mode:
  тёмный фон, круговые узлы-иконки, закрашенный+галочка / серый+замок —
  см. `design-brief-ui-elements.md`.
- Размещение секторов и колец на карте — универсальная функция от
  `Profession.domain_count`/`Profession.ring_count`, без хардкода под
  6 секторов/3 кольца PM: смена профессии — это новые данные
  (`SkillDomain`), не новый код рендера. См. `design.md`.

## Стек (зафиксировано на MVP)

### Frontend
- React + TypeScript, сборка через Vite
- D3.js (или чистый SVG, без отдельного canvas-движка) — рендер карты навыков
- Tailwind CSS — стили
- Hosting: Vercel или GitHub Pages (тот же паттерн, что уже используется для
  Telegram-бот-игры)

### Backend
- Node.js + TypeScript, Express или Fastify
- PostgreSQL + Prisma ORM — реляционная модель, нужна для агрегатных
  когортных запросов (percentile, stddev по срезам)
- Redis (или отдельная Postgres-таблица с timestamp) — кэш ответов
  агентного слоя с окнами свежести (тренды — раз в неделю, зарплаты —
  раз в месяц)

### AI / агентный слой
- Claude API — Sonnet для дешёвых частых запросов, Opus для тяжёлого
  когортного анализа
- MCP-серверы — job board API, зарплатные данные, Google Trends (через
  обёртку), каждый вызов логируется с полем "источник + дата данных"
- Правило источника: только структурированные API с полем даты
  обновления, не парсинг случайных сайтов; если источнику > 6 месяцев —
  визуальная пометка пользователю

### Данные для холодного старта
- Stack Overflow Developer Survey 2025 (results.csv из
  StackExchange/Survey на GitHub) — ETL-скрипт (Python/pandas или
  Node) → таблицы Cohort / CohortSkillBenchmark в Postgres

### Auth / прочее
- Auth: Clerk или Auth0 (email + LinkedIn OAuth)
- Payments/affiliate: Stripe (платная консультация) + партнёрские ссылки
  Coursera/Udemy с трекингом
- Analytics: PostHog
- CI/CD: GitHub Actions
- Тесты: Vitest

### Явно НЕ используем на этом этапе
- Unreal Engine / любой 3D real-time движок — продукт это 2D
  data-visualization, а не игра с окружением и камерой; см. обсуждение
  в чате от 2026-09-01. Пересмотреть только если продукт эволюционирует
  в полноценный 3D-мир с аватаром — не раньше, чем через несколько
  успешных итераций.

## Конвенции
- Код и коммиты — на английском, продуктовые документы/спеки — можно на
  русском (рабочий язык команды).
- Именование сущностей в БД — snake_case, в TypeScript-типах — PascalCase.
- Каждое обращение к MCP-источнику логируется с полем `fetched_at` и
  `freshness_window`, без исключений.
