# Дизайн-бриф: элементы интерфейса

Это бриф на уровне переиспользуемых компонентов, не на уровне целых
экранов. Целые страницы (онбординг-флоу, дашборд) собираются из этих
элементов позже, отдельным брифом, когда компоненты устоятся.

Референсы см. в `references.md`.

---

## 0. Визуальная система: MSFS-style (закреплено)

Референс — Microsoft Flight Simulator 2024, карьерный режим: радиальная
схема из круговых узлов-иконок на тёмном фоне, концентрические кольца
зрелости, состояние узла — заливка + иконка, не текстовая карточка.

**Соответствие сущностям:**
| Визуальный элемент референса | Сущность |
|---|---|
| Концентрические кольца на тёмном фоне | Геометрия карты в целом |
| Круговой узел-иконка | Один `Skill` |
| Позиция узла по кругу | `SkillDomain.order_index` → угол по формуле `angle = 360° / Profession.domain_count * order_index` |
| Расстояние узла от центра | `Skill.ring_index` → радиус по формуле `radius = R_max * ring_index / Profession.ring_count` |
| Зелёная рамка + галочка | Состояние "оценено" |
| Серый + замок | Состояние "не оценено / не открыто" |
| Линии между узлами | `SkillConnection` |

Формулы геометрии не зависят от визуального скина: если в будущем скин
сменится ещё раз (созвездия, что угодно другое), угол/радиус узла
считаются тем же кодом — меняется только то, что рисуется в точке
(angle, radius), не то, как она вычисляется. См. `design.md` →
"Ключевые решения дизайна данных".

**Палитра:** тёмный фон (не белый, как в исходном PAF Skill Map);
один устойчивый цвет-акцент на домен — тот же цвет используется в
подписи сектора и в `AIImpactBadge`.

---

## 1. SkillNode (узел карты навыков)

**Назначение:** базовая единица skill map — один навык. Круговой узел-
иконка на тёмном фоне, не прямоугольная карточка и не звезда-точка.

**Состояния:**
| Состояние | Визуал | Референс |
|---|---|---|
| Не оценено | Серая заливка, приглушённая обводка, иконка замка | MSFS: заблокированный узел |
| Оценено, ниже когорты | Заливка цветом домена, обычная яркость | MSFS: открытый, не top-tier узел |
| Оценено, выше когорты (+1 SD) | Заливка цветом домена + зелёная обводка + галочка | MSFS: "освоено" состояние |
| Требует подтверждения (inferred, не подтверждено) | Заливка цветом домена, пунктирная обводка + иконка "?" | — специфично для продукта: не выдавать предположение за факт |

**Обязательные под-элементы:**
- Название навыка (обрезка с тултипом на полный текст — при плотности
  71+ узлов подписывать все постоянно избыточно)
- Мини-бейдж устойчивости к ИИ — см. `AIImpactBadge` ниже
- Key_question — тултип при наведении/тапе

**Что НЕ делать:** не превращать это в 3D-изометрию с камерой — это
плоская 2D-иконка с состоянием на плоском тёмном фоне, MSFS тут референс
по эстетике узла и палитре, не по инженерному стеку (никакого Unreal/3D-
движка, см. `project.md` → "Явно НЕ используем на этом этапе").

## 2. AIImpactBadge (метка устойчивости к автоматизации)

**Назначение:** переносит на язык узла ту самую находку с картой PAF —
"звёзды скорости/качества + категория" — но компактнее, это мини-бейдж,
а не полноразмерный виджет как на исходной карте.

**Состояния категории (влияют на цвет бейджа):**
- `delegation` (зелёный) — можно делегировать ИИ, не самый приоритетный
  для прокачки человеком
- `mediated_via_prep` (оранжевый) — ИИ помогает готовиться, навык
  остаётся ценным
- `not_applicable` (серый) — вне зоны действия ИИ, инвестировать спокойно
- `replacement` (красный, единственный в исходной карте — задача
  исчезает) — явный сигнал "не туда"
- Индикатор "качество снижается" — отдельная красная иконка ▼ поверх
  обычных звёзд качества, не путать с состоянием `replacement`

**Взаимодействие:** клик по бейджу — короткое пояснение "почему это
важно" (1 предложение, без захода в теорию), не модалка на весь экран.

## 3. ConnectionLine (связь между навыками)

**Назначение:** визуализирует зависимость "нужно освоить X, чтобы перейти
к Y" — это то, ради чего вообще нужна карта, а не плоский список.

**Состояния:**
| Состояние | Визуал |
|---|---|
| По умолчанию | Тонкая линия, низкий контраст на тёмном фоне (MSFS: связи едва заметны, пока узел не выбран) |
| Активна (hover на связанный узел) | Утолщается, светится цветом домена-источника |
| Путь пройден (оба конца "оценено, выше когорты") | Сплошная, ровное свечение |

**Референс механики:** roadmap.sh — клик по узлу подсвечивает его прямые
связи, не весь путь целиком; берём тот же принцип поверх тёмной палитры
MSFS.

## 4. CohortMarker (маркер положения в когорте)

**Назначение:** единственный элемент, который реально доносит ключевую
метафору продукта — "ты не одна точка, ты точка на распределении".

**Форма:** горизонтальная шкала-гистограмма (не спидометр/gauge — тот
искажает восприятие стандартного отклонения) с:
- Затемнённой областью "среднее ± 1 SD"
- Вертикальной отметкой "ты здесь"
- Текстовой подписью процентиля ("выше 72% когорты")

**Референс:** Strava Fitness/Freshness score и percentile-сравнения в
беговых приложениях — тот же принцип "ты против распределения", не
абсолютное число.

**Что НЕ делать:** не использовать geймификационные "лиги"/таблицы
лидеров а-ля Duolingo для MVP — по продуктовому решению сегмент "сеньоры
на плато" может воспринять публичный рейтинг негативно; сравнение
приватное, один-на-один с распределением, не с именами других людей.

## 5. StructuralBarrierCallout (структурный барьер рынка)

**Назначение:** единственный компонент, который обязан выглядеть НЕ как
ошибка/проблема — это самый чувствительный элемент интерфейса,
продуктовое решение явно требует не пугать пользователя формальным
требованием.

**Визуальный тон:** информационный (нейтральный синий/серый фон,
иконка "i", НЕ красный/предупреждающий), обязательно вместе с
`exception_pct` в том же блоке, не отдельным мелким текстом ниже.

**Обязательная структура текста внутри:**
1. Факт: "X% людей на этой роли в этой стране имеют [диплом/сертификат]"
2. Контрбаланс в том же предложении или следующей строке: "Y% людей без
   этого всё равно на этой роли — обычно за счёт [портфолио/нетворка]"

**Референс:** нет прямого продуктового референса — по нашему решению это
уникальный для продукта паттерн честной, но не осуждающей подачи барьера.

## 6. OnboardingStepper (прогресс онбординга)

**Назначение:** держит онбординг в рамке 5–7 минут психологически —
пользователь должен видеть, что шагов мало.

**Форма:** горизонтальный прогресс из 3–4 шагов максимум (не больше —
цель бренд-обещания "5-7 минут" рушится визуально, если шагов 8).

**Референс:** Duolingo-онбординг — короткие экраны с одним решением на
экран, но БЕЗ маскота/сюжетных персонажей на этом этапе (не наш тон).

**Важная оговорка из ресёрча (Duolingo, 2022 редизайн):** линейный путь
даёт выше completion rate у новичков, чем свободное дерево. Для
онбординга (первый контакт) используем линейный степпер, а не радиальную
карту — карта навыков появляется только ПОСЛЕ онбординга, как результат,
не как форма ввода.

---

## 7. RecommendationCard (карточка roadmap-рекомендации)

**Назначение:** финал MVP-пути — 1–3 карточки с следующим шагом.

**Обязательные элементы:**
- Название навыка + короткий rationale (1-2 предложения, сгенерировано
  Claude, не шаблонная фраза)
- Мини-версия `AIImpactBadge` — обоснование "почему именно этот навык
  устойчив"
- CTA-кнопка — на MVP ведёт просто на дальнейшее чтение/ресурс, БЕЗ
  партнёрской монетизации (она вне скоупа MVP по `proposal.md`)

**Референс:** LeetCode/Codewars "следующая задача под твой уровень" —
принцип "одна конкретная следующая единица работы", не общий список.
