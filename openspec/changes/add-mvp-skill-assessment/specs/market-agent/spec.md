## ADDED Requirements

> Контракт на будущую итерацию. В MVP `MarketSignal` заполняется один раз
> ETL-скриптом из Stack Overflow Survey 2025, живых вызовов нет — но API и
> модель данных фиксируются сейчас, чтобы вторая итерация не ломала схему.

### Requirement: Свежесть рыночных данных проверяется перед показом
Система SHALL проверять `MarketSignal.fetched_at` против
`freshness_window` перед отображением и SHALL помечать сигнал как
устаревший, если прошло больше 6 месяцев, независимо от `freshness_window`.

#### Scenario: Сигнал в пределах окна свежести
- **WHEN** `now() - fetched_at < freshness_window`
- **THEN** сигнал показывается без пометки

#### Scenario: Сигнал старше 6 месяцев
- **WHEN** `now() - fetched_at > 6 месяцев`
- **THEN** `stale_flag = true` и интерфейс показывает визуальную пометку
  возраста данных рядом с сигналом

### Requirement: Источник данных — только структурированный API
Система SHALL получать `MarketSignal` только из источников со
структурированным полем даты обновления (API бирж вакансий, зарплатные
агрегаторы с версионированием) и SHALL НЕ использовать произвольный
веб-скрапинг без даты публикации.
